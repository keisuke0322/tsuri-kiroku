# フロントエンドの容量管理

本番ビルドはVinext / Viteの標準の最小化とツリーシェイキングを使用する。
変数名の短縮のための追加の難読化プラグインは不要。

## 背景画像

ログイン画面と季節のヒーロー画像は、元画像の構図を保ったWebPを
640px・1024px・元画像の幅で用意する。`srcSet` と `sizes` により、
ブラウザが表示幅と端末の画素密度に合う画像を選ぶ。

元画像は `public/images/login` と `public/images/hero` に保持する。
差し替えた場合は `corepack pnpm run artwork:generate` を実行し、
`public/images/optimized` の生成画像もコミットする。
生成は開発時のみ行い、通常ビルドやリクエスト時に画像変換はしない。
元画像のパスは互換性のため残すが、通常画面は最適化画像を参照する。

## CSS

Tailwindの走査対象は `app` と使用する `components/ui` のファイルに限定する。
未使用コンポーネントのファイルは残っていても、そのクラスからCSSを生成しない。
UI部品を追加するときは、その部品と依存する部品を `app/globals.css` の
`@source` に追加する。単体テストで追加漏れを検出する。
第三者のスタイル定義や共通スタイルを一括削除しない。

## カレンダー

日付入力のボタンは通常通り表示し、カレンダー本体と日本語ロケールは
登録・編集フォームを開いた際に先読みする。読み込み中はカレンダーに近い
大きさの領域に状態メッセージを表示し、カレンダーと操作ボタンをまとめて
表示する。初期の釣果一覧表示では読み込まない。
PC・スマートフォンで日付の選択・確定・再表示をE2Eで確認する。

容量比較は同じソース・依存関係で変更前後をビルドし、
`dist/client/.vite/manifest.json` の依存先も確認する。
分割後のJS合計容量と初期表示に必要な容量を区別し、gzipの試算値を
実際のHTTP配信サイズと同一視しない。
