# 釣果マップ（Issue #4）

## 動作と公開範囲

「自分の釣果マップ」から本人の釣行を魚種・開始日／終了日・今月／過去3か月／今年・お気に入りで絞り込む。釣り場またはピンを選ぶと釣行回数、最近の釣行日、魚種、匹数、最大サイズ、写真と釣行一覧を表示する。集計は選択した絞り込み条件に対応する。

既存の釣果1件を複数魚種を含む1回の釣行として扱い、場所名と座標を共有する。GPS・地図のクリック／タップ・ピンのドラッグ・過去の釣り場選択から登録できる。場所名検索は地図を移動し、利用者が地図で位置を指定する。GPSはボタンを押したときだけ取得し、拒否・タイムアウトでは手動指定できる。

**正確な座標と釣り場マスタは本人だけに表示・返却する。** 既存の釣り場名、釣果や写真の共有範囲は従来どおりログインユーザー間。地図利用時にはGoogleへ座標や場所名の検索語が送信される。地図はユーザーがマップまたは登録フォームを開いたときに読み込む。

位置付きの新規釣行を保存すると釣り場を自動保存し、次回選択できる。釣り場マスタの編集は名称と位置・お気に入りにのみ反映し、過去の釣行の場所名と座標は変更しない。過去の釣行は個別に編集する。位置未登録の既存データも引き続き利用できる。位置を解除して保存すると釣行の座標だけを削除する。

お気に入りは地図詳細で登録／解除する。過去の釣り場の選択肢ではお気に入りを先に表示する。同じ釣り場の釣行でも各釣行の実際の座標にピンを置く。#14のピンのクラスタリング、釣り場メモ・専用写真、地図から釣行開始は対象外。

## Google Mapsの設定

1. Google Cloudでプロジェクトと請求先を設定し、**Maps JavaScript API** と **Geocoding API** を有効にする。検索はMaps JavaScriptのGeocoderを利用し、Places APIは使用しない。
2. APIキーを作り、アプリケーションの制限を「ウェブサイト」にし、環境ごとに別キーを使う。HTTPリファラーの許可に該当環境のみを追加する。
   - staging: `https://tsuri-kiroku-staging.keisuke0322.workers.dev/*`
   - production: `https://tsuri-kiroku-production.keisuke0322.workers.dev/*`
3. API制限をMaps JavaScript APIとGeocoding APIに限定する。Google Cloudのクォータ上限と予算アラートを設定する。予算アラートだけでは課金は停止しないので、現在の料金・無料利用量を確認して上限を決める。
4. GitHub → Settings → Environments → **staging** の Variables に `GOOGLE_MAPS_API_KEY` を設定する。キーはブラウザに公開される性質のため、リファラーとAPI制限が必須。チャットやコードにキーを貼らない。
5. `cloudflare-migration` のDeploy Cloudflareを再実行するとstagingのWorker変数に反映される。productionは本番公開の手順に従い、productionのVariableに本番用キーを設定する。

ローカルではWranglerの `.dev.vars`（Git管理外）に `GOOGLE_MAPS_API_KEY` を設定し、ローカル専用キーに `http://localhost:5173/*` を許可する。本番キーの制限を外さない。

キー未設定時は地図を読み込まず「地図は準備中」を表示する。GPS取得・緯度経度の手動入力・過去の釣り場・お気に入り・検索結果の一覧・既存釣果機能は利用できる。Google地図の描画・ピン操作・場所名検索はキー設定後に確認する。

## DBと検証

`0006_fishing_map.sql` は `fishing_spots` と `catch_positions` の追加のみ。既存データの推測による座標補完や外部の釣り場マスターへの依存はない。位置は共有のcatchesとは別テーブルで、取得時に釣行所有者で絞る。旧クライアントがpositionを送らない編集では既存座標を維持する。

stagingでPC・スマートフォンの登録、GPS拒否後の手動指定、地名検索、ドラッグ、過去の釣り場再利用、お気に入り、魚種・期間、編集後の過去データ維持を確認する。座標の非公開・権限・入力境界・データ維持はAPIテストで確認する。Googleの実サービスによる地図操作はキー設定後の手動確認が必要。
